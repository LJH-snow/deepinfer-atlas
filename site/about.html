使用与归属

本地阅读、图形操作、导出、重新生成与上游归属说明。

怎样使用这份图谱

建议先按首页的 10 分钟路线阅读，再沿源码地图深入。正文和静态预览可直接打开；三个 Archify 图是自包含 HTML，点击“打开交互图”后可缩放、搜索、选择节点和追踪关系。页面采用独立打开方式，避免移动端在嵌入窗口中反复滚动；返回正文可使用浏览器返回。

图中标签比较密集时，使用放大按钮或浏览器缩放。键盘可聚焦工具栏；节点也可通过图形查看器提供的搜索入口定位。浅色 / 深色只改变图形配色，节点、关系与证据含义保持一致。查看器包含可选的 Google Fonts 请求，网络不可用时使用系统字体；站点正文不加载外部字体。

在窄屏上，交互图保留局部可读比例。可横向滚动画布查看其他区域，或点击放大镜搜索节点；正文预览帮助你先看清整体结构。

图形导出

图形右上角的“导出”提供 SVG、PNG、JPEG 和 WebP 等静态格式，具体以查看器菜单为准。默认交付为静态图，没有录制演示视频。导出只负责图形，不包含本文的证据表和解释边界；引用时请附上本次分析 commit 与页面上下文。

站点中的 PNG 预览来自同一份已验收的 Archify 图。维护者可用保存的 JSON 规格重新生成；不要把截图作为唯一可编辑源。查看实际验证记录，其中区分已测试的功能与查看器提供但本项目未逐项验证的功能。

本地预览与构建

打开仓库中的 site/index.html 即可阅读。推荐用本地 HTTP 服务检查图形导出和部署路径：

python3 scripts/build.py
python3 -m http.server 4173 --bind 127.0.0.1 --directory site

随后访问 http://127.0.0.1:4173/。构建只用 Python 标准库，会生成 site/ 并复制部署产物到 dist/；无需安装前端依赖或启动后台 API。没有 GPU / NPU 也能阅读、构建和验证本项目。

所有站点资源采用相对路径，可部署到域名根目录或项目子路径。当前站点已通过 GitHub Pages 发布；图谱仓库提供部署工作流，推送 main 后自动更新。Fork 后请在自己的 Pages 设置中启用 GitHub Actions。

怎样更新上游与重新生成

  1. 从 data/upstream.json 读取固定 SHA。执行 python3 scripts/fetch_upstream.py 获取精确 checkout；脚本不会自动跳到新 HEAD。
  2. 准备分析新版本时，先独立 checkout 新 SHA，重新检查主要路径、发布范围、配置条件和所有证据。不要只替换 URL 中的 commit。
  3. 修改 content/ 的文章与 data/evidence.json 的符号/片段范围；核心拓扑变化则更新 diagrams/specs/。
  4. 有 Archify 2.16 的环境可按维护文档运行 python3 scripts/diagrams.py，依次完成 validate、deliver、visual-check。每张图必须有 9/9 showcase、0 errors / warnings。
  5. 实际查看浅色、深色和移动端；重新导出预览，再构建并运行站点/源码检查。
